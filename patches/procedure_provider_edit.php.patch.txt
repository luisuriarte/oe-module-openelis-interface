# Patch: Add OpenELIS catalog credentials to the Procedure Provider edit form
#
# File: interface/orders/procedure_provider_edit.php
# OpenEMR version: 8.0.0 (tag v8_0_0) — ORIGINAL file
#
# This patch adds two fields ("OpenELIS Catalog Login" / "OpenELIS Catalog
# Password") to the Procedure Provider edit/add form. They persist into the
# module columns procedure_providers.mod_openelis_catalog_login and
# mod_openelis_catalog_password — the ADMIN user for the OpenELIS REST
# test-catalog API used by the module's bulk catalog import (catalog_import.php).
# It is a SECOND credential set: the stock Login/Password fields on this same
# form keep the operational user (Analyser Import) used by the order-send flow.
#
# NOTES:
#  - OpenEMR 8.0.0 builds $sets by embedding pre-escaped values inline
#    (invalue() / onvalue() / add_escape_custom()). This patch follows the
#    SAME style: the two catalog values are pre-computed in PHP variables just
#    before $sets, so no bound parameters are needed.
#  - The catalog password is rendered as type="password" and, when left blank
#    on an existing provider, the stored value is KEPT (it is never erased by an
#    unrelated edit). On brand-new providers a blank password stays blank.
#  - No new columns/DDL are required: mod_openelis_catalog_login/password are
#    created by the module's table.sql.
#  - Adapts cleanly to custom versions that add PACS/viewer fields
#    (remote_api, wado_url): keep YOUR columns, only exchange the LAST $sets
#    line for the catalog tail of STEP 2.
#
# INSTRUCTIONS:

# 3. Test by editing an existing provider and by adding a new one.
#
# Optionally (Spanish site): the new labels are translated by the module's
# sql/lang_custom.sql ("OpenELIS Catalog Login", "OpenELIS ADMIN user",
# "Leave blank to keep the stored password", plus the three help strings).
# Re-run that file to pick them up.

## ============================================================
## TROUBLESHOOTING the "empty error" save failure
## ============================================================
## If saving fails with an EMPTY text after "Error:" (e.g.
## "Failed to execute statement. Error:  Statement: UPDATE ..."), the
## statement sent to MySQL is malformed. Verify against the DEPLOYED file:
##
##   - Every column in $sets has a value with the right helper:
##     invalive('form_xxx') for text fields, onvalue('form_xxx') for the
##     active checkbox, add_escape_custom($var) for the two catalog columns.
##   - Quoting is balanced: each column is quoted as "col = value", with a
##     trailing "," on all lines except the last.
##   - Custom files with extra columns (remote_api, wado_url) keep ALL of
##     them: only the last line ("active = ...") changes.
##
## NOTE: the "empty error" is the ADOdb/mysqli signature for a broken
## statement (typically a placeholder/value mismatch in versions that use
## bound parameters).
