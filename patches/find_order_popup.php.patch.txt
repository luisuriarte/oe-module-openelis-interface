# PREMISE
# The picker is opened from the Procedure Order form carrying the selected
# "Sending To" lab in $_GET['labid'] (procedure_providers.ppid). Before this
# patch the SEARCH listing never used labid in its WHERE for catalog rows that
# carry a procedure_type_name (i.e. every test imported by catalog_import.php),
# so tests from ALL labs showed up mixed together regardless of the chosen lab.
# That defeats the multi-provider architecture where the same test exists per
# lab (OE4-T42 vs OE5-T42) with procedure_type.lab_id = the real provider.
#
# WHAT THE DIFF DOES
#  1. Adds a global `AND lab_id IN (?, 0)` to BOTH branches of the search
#     listing (otype search and favorites/plain search). The `0` keeps rows of
#     the generic unassigned lab (lab_id = 0, e.g. manual LAB01) visible under
#     ANY selected lab.
#  2. When no lab is selected yet (labid = 0 / absent) NO lab clause is emitted:
#     the picker shows the full catalog as a fallback until the user picks
#     "Sending To".
#  3. Removes the old legacy sub-condition `AND pt.lab_id = ?` from the
#     procedure_type_name branch (now covered by the IN), so legacy lab_id = 0
#     rows also stay visible under any selected lab.
#  4. Groups the imaging `OR pt.parent IN (subtree)` INSIDE the
#     procedure_type_name condition, so the lab_id filter applies via AND to
#     BOTH routes instead of being escaped by the OR (the previous structure
#     left the imaging subtree unfiltered).
#
# NOTE: this diff is against the PRISTINE OpenEMR 8.2.0 file and therefore also
# contains the earlier "otype" patch (search filtered by procedure_type_name,
# with an imaging DIAGNOSTIC IMAGING-subtree fallback). On sites that already
# applied that otype version, only the lab-scoping hunks are new.
# The COMPLETE patched file is available at
# patches/openemr/interface/orders/find_order_popup.php (production-ready: copy
# it over interface/orders/find_order_popup.php).
#
