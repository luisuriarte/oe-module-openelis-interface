# Patch: Strict per-provider scoping in the Procedure Picker (find_order_popup.php)
#
# File: interface/orders/find_order_popup.php
# OpenEMR version: 8.2.0 - ORIGINAL file baseline
#
# PREMISE
# The picker is opened from the Procedure Order form carrying the selected
# "Sending To" provider in $_GET['labid'] (procedure_providers.ppid, matching
# procedure_type.lab_id) and the order type in $_REQUEST['otype']
# (procedure_type.procedure_type_name). Before this patch the old WHERE always
# forced `lab_id = ?` (only rows of the chosen lab) with no combination with the
# procedure type, so the catalog could not be restricted to exactly the tests of
# the selected provider AND the selected type.
#
# WHAT THE DIFF DOES
#  1. Filters by provider using ONLY procedure_type.lab_id: for a selected lab
#     (labid > 0) the search is limited to THAT provider's rows exclusively
#     (strict AND lab_id = ?) — no mixing with the generic unassigned lab.
#  2. Filters by procedure type using ONLY procedure_type.procedure_type_name
#     when an otype is selected ('imaging' shows the DIAGNOSTIC IMAGING subtree
#     via pt.parent as a same-table fallback; other types match rows whose
#     procedure_type_name equals the requested type). The provider (lab_id) and
#     the type (procedure_type_name) combine with AND, so picking a provider that
#     has no items of that type returns an EMPTY result (e.g. Imagen Services
#     + 'procedure' -> nothing).
#  3. Legacy rows WITHOUT a loaded procedure_type_name are still shown when they
#     belong to the selected lab, so nothing is lost.
#  4. When no lab is selected yet (labid = 0 / absent) NO lab clause is emitted:
#     the picker shows the full catalog as a fallback until the user picks
#     "Sending To".
#  5. Groups the imaging `OR pt.parent IN (subtree)` INSIDE the
#     procedure_type_name condition, so the lab_id filter applies via AND to
#     BOTH routes instead of being escaped by the OR.
#  6. Favorites (fgp) are left unfiltered by type so custom groups are not
#     broken, but are still lab-scoped (strict lab_id = ?).
# The search box (code/name LIKE) and activity = 1 are the native picker filters
# and are untouched.
#
# NOTE: this diff is against the PRISTINE OpenEMR 8.2.0 file and therefore also
# contains the earlier "otype" patch (search filtered by procedure_type_name,
# with an imaging DIAGNOSTIC IMAGING-subtree fallback). On sites that already
# applied that otype version, only the lab-scoping hunk is new.
# The COMPLETE patched file is available at
# patches/openemr/interface/orders/find_order_popup.php (production-ready: copy
# it over interface/orders/find_order_popup.php).
#
